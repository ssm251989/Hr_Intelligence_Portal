20.2 AGENT: ONBOARDING COMPLETED -> EMPLOYEE CREATED

Trigger: onboarding case status = Completed (or HR clicks
"Mark onboarding complete"). The Onboarding agent then:
1. Checks the Employee list for an existing record (same personal email,
   phone, PAN, or same candidate id). If found -> link, don't duplicate;
   if a possible match -> ask HR in the to-do list ("Is this the same
   person as CTD-0007?").
2. Creates the employee record from candidate + offer + joining form:
   name (first/last/preferred), designation, department, manager,
   location, joining date, employment type, previous experience,
   personal email/phone, emergency contact, bank/ID (masked).
3. Generates the Employee ID.
4. Company email:
   - Suggests the address from a configurable pattern
     (Settings: e.g. firstname.lastname@ctdtechs.com; fallback patterns if
     taken: firstname.l, firstname.lastname2) and checks it is free.
   - If an email-admin connection is set up (Google Workspace Admin API or
     Microsoft 365 / Entra via Graph - new connection types, credentials in
     SecretStore), creates the mailbox with a one-time password that is
     NEVER stored or emailed in plain text: the person gets a "set your
     password" link from the provider, or the temp password is shown once
     to HR on screen.
   - If no connection: creates an IT to-do "Create mailbox
     kishore.gunda@ctdtechs.com for Kishore Gunda (joins 14 Oct)" with a
     "Done - mailbox created" button where HR/IT confirms the address.
5. Creates the HR Automation app account: login = company email, role
   Employee (plus roles from rules, e.g. designation -> Interviewer),
   sends an invite to the company email (and personal email as backup)
   with a "Set your password" link (expires in 72h, resend option).
6. Moves the person from Onboarding to Employees, status Active;
   onboarding card shows "Employee created - CTD-0012".
Human-in-the-loop: Settings > Onboarding & employees > "When onboarding
completes": (a) agent prepares, HR approves with one click (DEFAULT),
(b) fully automatic. The approval card shows everything the agent will
create (ID, email, roles) and HR can edit before approving.
Everything audit-logged; failures (e.g. mailbox API error) shown in plain
words with Retry, never silent.

20.3 EMPLOYEE SELF-SERVICE (employee logs in)

Employee home (simple): My profile (view, request changes -> HR approves),
My documents/letters, My assets, Raise exit, and - if interviewer - My
interviews. Only their own data (permission-scoped).

Exit by the employee ("Resign"):
- Form: reason (list + note), proposed last working day (defaults to
  joining-rule notice period, shown in plain words "Your notice period is
  60 days -> 5 Dec 2026"), request early release yes/no, upload
  resignation letter (optional).
- Approval workflow: Manager -> HR (configurable); manager can add a
  retention discussion note; HR confirms last working day.
- Status visible to the employee: Submitted / Manager approved / HR
  approved - last day <date> / Withdrawn. Employee can withdraw before HR
  approval.
- Then clearance checklist (assets to return, access removal, handover,
  documents) with owners; exit interview form (optional); relieving and
  experience letters from templates when completed.
HR can also start an exit from the Employee list (Resigned / Terminated /
Absconded with the absconding email flow from the earlier fix).
On exit completed (last working day passed + clearance done):
- App account disabled; company mailbox suspended via the email-admin
  connection (or IT to-do if not connected); removed from interviewer
  pools; future interviews reassigned (to-do to HR); status Exited;
  record kept (never deleted); rehire eligible flag.

20.4 EMPLOYEE AS INTERVIEWER

- "Make interviewer" (Employee list / profile) adds role Interviewer and
  lets HR choose skills/jobs/pools. Rule option: auto-add by designation or
  department (Settings).
- The employee then sees: My availability (weekly grid, block dates, max
  interviews per day), My interviews (calendar + list), candidate profile
  ONLY for candidates assigned to them (resume, match score, AI questions),
  scorecard submit, propose reschedule, decline with reason.
- Scheduling uses their availability; invites go to their company email.
- Interviewer cannot see salary, other candidates, or settings.
- Reminders: scorecard pending after X hours (configurable).
- Existing interviewers (e.g. "jr") are linked to employee records by
  email; if no match, HR gets a to-do to link or create.
