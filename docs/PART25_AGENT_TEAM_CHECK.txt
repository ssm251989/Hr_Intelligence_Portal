25.2 REAL MODEL CHECK (API from backend/.venv; clean test data; Mailpit on; record each answer +
the "Agent team" panel screenshot in docs/ui/FIXES_25.md). Demo data: one job with 3 screened
candidates, one candidate at each later step (interview_selected above band, salary_approved with
documents uploaded, bgv_pending, bgv_cleared, a joiner whose joining date is today, one open exit
with clearance done). Ask the HR assistant:
  a. "Create a job for a Senior Python Developer in Chennai, 4 to 7 years, Django and AWS"
     -> Job agent: DRAFT + JD; job shows Ready for publishing; nothing published.
  b. "Create a job for a QA engineer in Bengaluru and screen any applicants"
     -> Job agent hands to the Screening agent (agent-to-agent); panel shows both.
  c. "Shortlist the top 2 candidates for <demo job>" -> ONE card; approve -> Shortlisted and
     interview scheduling starts (Mailpit).
  d. "Who is waiting for an interview for <demo job>? Re-send the slots to <name>"
     -> Interview agent answers and re-sends.
  e. "Check <above-band name>'s salary" -> Salary agent explains band/expected and proposes a
     decision card; approve -> Salary approved, documents form email (Mailpit).
  f. "What's pending on <documents name>'s documents? Approve them if all are fine"
     -> Documents & BGV agent reports flags and proposes approval (card); approve -> BGV requested.
     Then "Send <name>'s BGV to <vendor>" -> vendor card; approve -> vendor email (Mailpit).
  g. "BGV for <bgv_pending name> came back clean, and offer joining dates"
     -> BGV agent proposes passed (card) and hands to the Offer agent; after approving the BGV
     card ask again -> Offer agent proposes 3 dates (card); approve -> joining-dates email.
  h. "Who joins today?" -> Onboarding agent; "Mark <joiner> as joined" -> card; approve ->
     employee record created.
  i. "What blocks <leaver>'s relieving letter?" -> Exit agent; if nothing blocks -> letters card.
  j. "Take <name> from salary through to the offer" -> one request, several agents in sequence;
     the panel shows each hand-off; only cards are created, nothing decided.
  k. A user WITHOUT recruitment.job.create asks (a) -> polite refusal, no job.
     An employee with no HR permission asks (c) -> normal assistant path, no agents.
  l. "What is the notice period for a senior employee?" -> normal handbook answer with source.
     "Show my offer letter" -> self-service path, not the team.
  m. Settings: copilot.agents.enabled off -> (a) goes the old way; back on. Switch off
     agents.salary in AI Intelligence > Features -> (e) says the Salary agent is not available.
For each: AI Intelligence usage page shows the cost per agent feature (agents.*).
