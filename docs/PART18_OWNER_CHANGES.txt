18.4 MODULE UNLOCK PASSCODE
- Each main module (Jobs, Candidates, Screening, Shortlisting, Interviews,
  Candidate emails, Salary, BGV, Offers, Onboarding, Reports, Settings,
  GenAI usage, and any other enabled module) is LOCKED until an admin enters
  the module passcode once on Settings > Modules (or on the locked page).
- Passcode stored only as a bcrypt hash in the database, never in code or
  git. Set it for this installation with a CLI command:
    hrctl modules set-passcode --tenant <slug>   (prompts, not in history)
  Owner will set the current value; super-admin can change it any time
  (Settings > Modules > Change passcode, needs current passcode).
- Options (settings): one passcode for all modules (default) or a different
  passcode per module; unlock lasts until re-locked by admin; wrong attempts
  limited (5, then 15-minute lock); every unlock/lock is in the audit log.
- Locked module = menu item shows a lock icon, page shows a friendly
  "This module is locked - enter passcode" card. APIs of locked modules
  return 403 with a plain message.

D. POST-INTERVIEW AUTOMATION (agent-driven, configurable)
==========================================================================
Stage flow: Interview cleared -> Salary form -> Salary decision ->
Documents form -> Documents review -> BGV -> Joining date -> Offer letter +
Welcome onboarding. Every automatic email uses an editable template; every
step logs to the candidate timeline; HR can override any step.

18.12 SALARY FORM (automatic)
- When a candidate clears the interview (configurable: which round), the
  agent emails a branded "Salary details" form automatically: current CTC,
  expected CTC, notice period, offers in hand (optional), payslip upload
  (optional, setting). Reminder after 24h and 48h (configurable).

18.13 SALARY AUTO-DECISION
- Settings > Hiring > Salary rules:
  * auto-approve if expected hike over current CTC <= X% (default 20%,
    editable, e.g. 10-20);
  * AND expected CTC within the job's salary band;
  * AND the department budget has enough remaining (18.15).
- Otherwise the candidate is highlighted in the Salary table (red chip
  "Above company range - check" / "Hike 35% > 20% limit" / "Department
  budget short by 4 L") and needs HR approval (approve / counter-offer
  amount / reject with reason).

18.14 SALARY PAGE = TABLE + BULK
- DataGrid of all candidates at salary stage: name, job, department,
  current CTC, expected CTC, hike %, band min-max, budget impact, status
  chip (Waiting for form, Auto-approved, Needs approval, Approved,
  Rejected), days waiting. Filters, sort by hike %, bulk approve, export.
  Row click opens a side panel with details and history - no scrolling
  through cards.

18.15 DEPARTMENT HIRING BUDGET + FINANCE DASHBOARD
- Settings > Hiring > Department budgets: per department and financial year:
  allocated amount (e.g. 50 L), optional per-quarter split, alert threshold
  (e.g. 80%), what happens when exceeded (needs approval / block).
- Money tracking: "Reserved" when salary approved, "Committed" when offer
  accepted, released if the candidate drops out.
  Example: department budget 50 L, hire at 10 L -> remaining 40 L.
- Salary > Finance dashboard: per department allocated / reserved /
  committed / remaining with coloured bars, trend by month, top roles by
  cost, alerts. Export to Excel.

18.16 DOCUMENTS FORM (automatic after salary approval)
- As soon as salary is auto-approved or HR-approved, the agent emails a
  "Documents upload" form. Settings > Hiring > Required documents: list
  of document types (PAN, Aadhaar, education certificates, experience
  letters, last 3 payslips, relieving letter, photo, etc.), each required
  / optional, allowed file types, max size. Different lists per job type
  allowed. Reminders configurable.

18.17 DOCUMENTS REVIEW (agent highlights, HR approves)
- When files arrive, the agent checks each one (AI): right document type,
  readable, name/DOB match across documents, missing items, expired dates -
  and highlights: green OK, amber check, red problem, with the reason.
- HR sees a review table, approves all / per document, or asks for
  re-upload of specific documents (agent emails the candidate with the
  list). On HR approval the candidate moves to BGV automatically.

18.18 BGV DECISION BY HR (no automatic "failed")
- When BGV feedback arrives, HR decides: Passed / Resend form / Failed.
  * Resend form: agent emails the candidate a new upload form listing
    exactly what is needed (HR note included).
  * Failed: HR must give a reason; agent emails the candidate a polite
    "BGV unsuccessful" message with the HR reason (template editable,
    HR can preview/edit before sending).
- System never marks BGV failed by itself.

18.19 JOINING DATE (3 options)
- After BGV passed, HR picks 3 tentative joining dates. Agent emails the
  candidate "Background verification successful" + the 3 dates to choose
  from (one click). Reminder if no answer in 48h; HR can propose new
  dates. Chosen date saved and shown to HR.

18.20 OFFER LETTER + WELCOME (automatic after date confirmed)
- When the candidate confirms a date, the agent sends: the offer letter
  (generated from template with salary + joining date, e-sign via the
  connected DocuSign), and a happy "Congratulations on your selection"
  welcome email with onboarding steps and contact details: HR, department
  head, management - taken from Settings > Hiring > Contacts per
  department (name, role, email, phone), editable.
- Candidate moves to Onboarding (pre-joining portal) automatically.
