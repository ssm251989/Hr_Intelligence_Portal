16.4 BULK RESUMES + WHERE DATA IS STORED (~1000 resumes per run)
Today: candidate data is in PostgreSQL; resume files go to
backend/uploads/resumes/ with random names, NOT separated per company and
NOT using the storage connection. Fix:
- All files (resumes, photos, BGV docs, offer letters, employee documents,
  exports, welcome videos) go through the StorageProvider, path
  tenants/<company-id>/<kind>/<yyyy>/<mm>/<uuid>.<ext>.
  Dev default: local folder backend/storage/. Production: S3 in ap-south-1.
- One-off migration command `hrctl storage migrate-local --dry-run` then
  real run: moves existing files into the new layout and updates the DB
  paths. Never deletes the old file until the copy is verified.
- Bulk import screen: drag in many files or one ZIP (up to 1000 resumes),
  shows a cost/time estimate first (AI parsing calls), then processes in the
  background queue with a live progress bar (x of 1000, failed, duplicates),
  pause/resume, and a downloadable result report (Excel).
- Duplicate detection by file hash + email/phone before parsing.
- Rate-limited AI parsing in batches; failures retry, then listed with reason.
- Settings > Integrations > File storage page shows plainly where files are
  kept and how much space is used.
